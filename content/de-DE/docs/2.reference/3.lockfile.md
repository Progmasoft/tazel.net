`LOCK.sqlite3` liegt neben der Projektdatei. Es ist eine SQLite-Datenbank, die festhält, was das Projekt deklariert:
seine Abhängigkeiten mit ihren Features und die Plugins, die die Projektdatei ausgewertet haben, mit dem Digest jedes
JARs. Sie hält Deklarationen fest, keinen aufgelösten Abhängigkeitsgraphen; Tazel kann noch keine Pakete aus ViGet
laden, also gibt es nichts aufzulösen.

Committen Sie `LOCK.sqlite3` mit der Projektdatei. Ihre Textform, `LOCK.dump`, dient zum Lesen und zum Prüfen einer
Änderung.

## Wann sie geschrieben wird

| Befehl | Was mit `LOCK.sqlite3` geschieht |
| --- | --- |
| `tazel lock resolve` | wird für das Projekt und für jedes Mitglied seines Workspace geschrieben |
| `tazel check`, `build`, `run` | wird vor dem Kompilieren eines Projekts geschrieben, wenn sie nicht mehr festhält, was das Projekt deklariert |
| `tazel lock graph` | wird geschrieben, wenn sie fehlt oder veraltet ist; mit `--locked` ist eine veraltete Datei stattdessen ein Fehler |
| `tazel lock create-dump` | wird nur gelesen |

Ob sie „veraltet“ ist, entscheidet der Inhalt: Tazel liest die Datei und vergleicht, was sie festhält, mit dem, was die
Projektdatei jetzt deklariert. Eine Datei eines älteren Formats, eine beschädigte und eine fehlende Datei sind alle
veraltet.

Eine neue Lockdatei wird in eine temporäre Datei im selben Verzeichnis geschrieben und dann über die alte verschoben,
atomar, wo das Dateisystem es erlaubt; ein unterbrochenes Schreiben hinterlässt also nie eine halbe Lockdatei.

## Format 5

Die Tabelle `metadata` hält das Format: `format_version` ist `5`. Format 5 ist Format 4 mit der Stabilität `RC`, eine
Datei im Format 4 wird also so gelesen, wie sie ist, und bleibt, bis sich das Projekt ändert. Eine Lockdatei eines
anderen Formats wird nicht gelesen; Tazel verlangt `tazel lock resolve`, das das aktuelle schreibt. Versionen von Tazel
vor Format 5 lehnen eine Datei im Format 5 ebenso ab.

| Tabelle | Schlüssel | Spalten |
| --- | --- | --- |
| `metadata` | `key` | `value`; hält `format_version` |
| `packages` | `name`, `scope` | `stability`, `version`, `feature` (das Feature dieses Projekts, das das Paket einbringt, oder `NULL`), `default_features` (`0` oder `1`) |
| `package_features` | `package_name`, `scope`, `feature` | `enabled` (`0` oder `1`): die Features der Abhängigkeit selbst, die das Projekt ein- oder ausschaltet |
| `local_packages` | `path`, `scope` | die `.vipkg`-Dateien, die das Projekt nennt, relativ zur Projektdatei |
| `plugins` | `publisher`, `name` | `version`, `api_version`, `sha256` (64 Hexadezimalziffern) |

`name` in `packages` ist die Koordinate des Pakets, `Publisher.Name`. `scope` ist `BUILD` für `dependency` und
`localDependency`, `TEST` für `testDependency` und `localTestDependency`. Jede Tabelle ist `WITHOUT ROWID`: Eine Zeile
wird allein durch ihren Schlüssel bestimmt, also kann ein Paket in einem Scope nicht zweimal festgehalten werden.

Für diese Projektdatei:

```kotlin
dependencies {
  dependency("Publisher") {
    name = "Toml"
    version = "1.0.0"
    feature = "TOML"
    defaultFeatures = false
    feature("Serde") { enabled = true }
  }
  localDependency { path = "Libraries/Shared.vipkg" }
}
```

hält die Lockdatei:

| Tabelle | Zeile |
| --- | --- |
| `packages` | `Publisher.Toml`, `BUILD`, `STABLE`, `1.0.0`, `TOML`, `0` |
| `package_features` | `Publisher.Toml`, `BUILD`, `Serde`, `1` |
| `local_packages` | `Libraries/Shared.vipkg`, `BUILD` |

## Der Text-Dump

```text
tazel lock create-dump
tazel lock create-dump --path reviews/Locks.sql
```

`LOCK.dump` ist SQL, das SQLite wieder abspielen kann: ein Kopfkommentar, `PRAGMA foreign_keys=OFF;`, dann eine
Transaktion mit der `CREATE TABLE`-Anweisung jeder Tabelle, gefolgt von ihren Zeilen. Die Tabellen kommen in der
Reihenfolge ihrer Namen und die Zeilen in der Reihenfolge ihrer Spalten, also ergibt dieselbe Lockdatei immer dieselben
Bytes, und ein Diff zeigt nur, was sich geändert hat.

So wird aus einem Dump wieder eine Datenbank:

```text
sqlite3 LOCK.sqlite3 < LOCK.dump
```

Der Dump wird nie über die binäre Lockdatei geschrieben, und sein Ordner muss existieren; siehe
[den Befehl](/docs/reference/commands#die-lockdatei-als-text-schreiben).

## Der Abhängigkeitsgraph

`tazel lock graph` zeichnet, was die Lockdateien festhalten, und erneuert sie deshalb zuerst. Es zeigt jedes Projekt des
Workspace als Wurzel, darunter seine ViGet- und lokalen Pakete und die Testabhängigkeiten unter `[test]`. Ein Paket, das
ein Feature einbringt, wird nur angezeigt, solange dieses Feature eingeschaltet ist. Die Optionen sind beim
[Befehl](/docs/reference/commands#der-abhängigkeitsgraph) beschrieben.
