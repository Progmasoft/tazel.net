Ein Projekt ist ein Ordner mit einer Projektdatei namens `BUILD.kts`, `BUILD.tzl`, `BUILD.tazel`, `BUILD` oder
`Tazel.build`. Dieses baut ein Tala-Programm: Seine Quellen sind die `.tala`-Dateien unter `Sources/`, und `entry`
nennt die Klasse, deren `public static void Main()` das Programm startet. Ein Projekt in C oder C++ verwendet
stattdessen den Block `cc { }` des [Plugins](/docs/extending/plugins) Progmasoft.CC und braucht kein Tala-Werkzeug.

```kotlin [BUILD.kts]
project {
  name = "Example"
}

sources {
  executable {
    entry = "Example.Program"
  }
}
```

```tala [Sources/Main.tala]
namespace Example;

public class Program {
    public static void Main() {
        Console.Println("Hello from Tala!");
    }
}
```

## Bauen und starten

```bash [terminal]
tazel build
tazel run -- first second
```

`tazel build` schreibt `build/debug/Example`, unter Windows `Example.exe`. `tazel run` baut das Programm und startet
es; was nach `--` folgt, geht ungelesen an das Programm. Ein zweites `tazel build` ohne Änderung meldet das Ziel als
aktuell und startet keinen Compiler.

## Formatieren und prüfen

```bash [terminal]
tazel fmt -- --check
tazel lint -- --fix
```

Optionen nach `--` gehen an talafmt und talalint, also meldet `tazel fmt -- --check` nur, und `tazel lint -- --fix`
wendet die Korrekturen an, die es kann.

::note
ViGet liefert keine Tala-Pakete aus. Ein Projekt, das eine Abhängigkeit des Builds deklariert, Bibliotheksziele und die
Erstellung von `.vipkg` werden mit Namen und Exit-Code 1 abgelehnt.
::
