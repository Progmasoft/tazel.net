Проект описывается одним файлом — скриптом Kotlin, который вычисляет [Tazel](/docs/reference/commands). Tazel читает его,
находит исходники, которые он называет, и запускает инструменты, которые их собирают; сами эти инструменты файла проекта
никогда не видят.

## Поиск

Файл проекта носит одно из пяти имён. Tazel ищет их в таком порядке и использует первое существующее; остальные не
читаются:

1. `BUILD.kts`
2. `BUILD.tzl`
3. `BUILD.tazel`
4. `BUILD`
5. `Tazel.build`

Имена чувствительны к регистру на любом хосте, и у всех пяти один и тот же синтаксис. Команда работает с проектом текущего
каталога: ближайшим каталогом вверх, в котором есть файл проекта.

Скрипт компилируется и выполняется внутри Tazel. Машине нужна JRE 25 или новее и не нужна установка Kotlin.

## Минимальный проект

```kotlin
project {
  name = "Example"
}

sources {
  executable {
    entry = "Example.Program"
  }
}
```

```powershell
tazel run
```

Это компилирует каждый файл `.tala` в `Sources/` и записывает `build/debug/Example.exe` (без расширения вне Windows).

[`BUILD.kts`](https://github.com/Progmasoft/tazel/blob/main/BUILD.kts) показывает весь DSL в одном файле. Чего нет в этом
файле, то не входит в DSL.

## `project`

```kotlin
project {
  name = "Example"
  version = "0.1.0"
  stability = Stability.STABLE // STABLE, RC, UNSTABLE, BETA, NIGHTLY, ALPHA or DEV
  description = "An example project"
  authors("Leitwolf", "Helmut")
  defaultFeatures("TOML")
  defaultRun = "Server" // the executable `tazel run` runs when none is named; default: the only one
}
```

`name` обязателен всегда, поэтому в каждом файле проекта есть блок `project`. Любое другое поле само по себе
необязательно. С `sources.viget.push = true` обязательны также `version`, `stability`, `description` и хотя бы один
автор; это проверяется после выполнения всего файла, поэтому порядок блоков не важен. `name` — один идентификатор, а
`version` — точная версия: `A.B.C`, затем при необходимости `.D`, `.E` и `-METADATA`.

## `compiler`

```kotlin
compiler {
  standard = talaStandardOf(26)
  backend = Backend.LLVM
  buildMode = BuildMode.RELEASE
  werror = true
  warnings = Warnings.ALL
  wshadow = true
  xppOptimizationPasses = true
  xmmOptimizationPasses = true
  optLevel = OptLevel.O3
  staticTalaRTLibrary = true

  llvm {
    compiler = LlvmCompiler.AOT
    lto = LlvmLto.NONE
    args("-time-passes")
  }
}
```

Этот блок относится к целям Tala; он настраивает Talac.

| Настройка | Значения | По умолчанию | Параметр компилятора |
| --- | --- | --- | --- |
| `standard` | `talaStandardOf(26)` | `talaStandardOf(26)` | `--standard` |
| `backend` | `Backend.LLVM` | `LLVM` | `--codegen-backend` |
| `buildMode` | `BuildMode.DEBUG`, `RELEASE` | `DEBUG` | выбирает выходной каталог и `optLevel` по умолчанию |
| `werror` | `true`, `false` | `false` | `--warnings-as-errors` |
| `warnings` | `Warnings.ALL`, `MEDIUM`, `LOW`, `NONE` | `MEDIUM` | `--warnings` |
| `wshadow` | `true`, `false` | `false` | `--warnings=shadow` |
| `xppOptimizationPasses` | `true`, `false` | `true` | `--xpp-optimization-passes` |
| `xmmOptimizationPasses` | `true`, `false` | `true` | `--xmm-optimization-passes` |
| `optLevel` | `OptLevel.O0`, `O1`, `O2`, `O3`, `OG`, `OS`, `OZ` | `O0` для `DEBUG`, `O3` для `RELEASE` | `--opt-level` |
| `staticTalaRTLibrary` | `true`, `false`, `null` | `null` | `--static-talart-library` |
| `llvm.compiler` | `LlvmCompiler.AOT`, `ORC` | `AOT` | `--llvm-compiler` |
| `llvm.lto` | `LlvmLto.FAT`, `THIN`, `NONE` | `NONE` | `--llvm-lto` |
| `llvm.args(...)` | аргументы для LLVM | нет | `--llvm-args` |

Tazel записывает каждую настройку в командную строку компилятора, в том числе со значением по умолчанию, поэтому сборка
следует из файла проекта, а не из значений по умолчанию того компилятора, который установлен. Настройку, которую
компилятор пока не умеет выполнить, компилятор отклоняет по имени; см.
[справку по компилятору](/docs/reference/commands#пока-не-реализовано).

Исключение — `staticTalaRTLibrary`. `null` или отсутствие настройки не записывает никакого параметра и оставляет выбор
компилятору; `true` записывает `--static-talart-library=true`, что компонует TalaRT в результат, а `false` записывает
`--static-talart-library=false`, что оставляет его в разделяемой библиотеке рядом с результатом.

Ни один уровень предупреждений не включает `wshadow`. `wshadow = true` вместе с `Warnings.NONE` — противоречие, и оно
отклоняется.

## `buildCache`

```kotlin
buildCache {
  local {
    enabled = true
    maxEntries = 8
  }

  remote {
    url = "https://cache.example.com"
    read = true
    write = false
    token = System.getenv("TAZEL_CACHE_TOKEN")
    publicKey = "MCowBQYDK2VwAyEA..."
    signingKey = System.getenv("TAZEL_CACHE_SIGNING_KEY")
  }
}
```

| Настройка | Значения | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `local.enabled` | `true`, `false` | `true` | хранит результаты в `.tazel/cache` |
| `local.maxEntries` | 1 или больше | `8` | сколько результатов каждой цели сохраняется |
| `remote.url` | адрес `https`; `http` только для этой машины | обязательно | где лежат общие результаты |
| `remote.read` | `true`, `false` | `true` | запрашивает результаты у сервера |
| `remote.write` | `true`, `false` | `false` | отправляет результаты на сервер |
| `remote.token` | текст или `null` | `null` | отправляется как `Authorization: Bearer`; пустой считается отсутствующим |
| `remote.publicKey` | ключ Ed25519 или `null` | `null` | используются только результаты, подписанные для этого ключа |
| `remote.signingKey` | ключ Ed25519 или `null` | `null` | подписывает то, что записывает эта машина; секрет |

Блок необязателен, и без него у проекта есть только локальный кэш. Локальный кэш имеет приоритет: у сервера запрашивается
только то, чего в нём нет, а полученное сохраняется локально, если `local.enabled` не равно `false`. Что делает результат
тем же самым, описано в разделе [инкрементные сборки](/docs/reference/commands#инкрементные-сборки).

Записывайте токены и ключ подписи как переменные, никогда — в файл проекта. Файл проекта, который читает переменную через
`System.getenv("NAME")`, получает значение команды, в том числе под демоном: если значение отличается от того, с которым
запущен демон, команда выполняется без демона и останавливает его, а следующая команда запускает демон, который видит
новое значение. Для этого имя должно быть записано текстом; имя, вычисленное во время выполнения, не замечается.

Результат — это программа, поэтому результат с сервера — это код, который эта машина выполнит. `tazel cache keygen`
выводит пару ключей Ed25519. Дайте `publicKey` каждому проекту, а `signingKey` — только тому, что собирает доверенные
исходники, например CI на основной ветке. Тогда читатель с `publicKey` использует результат только с подписью для этого
ключа, для этой цели и этого ключа кэша, поэтому ни утёкший токен, ни взломанный сервер не могут подложить программу.
Результат без подписи считается отсутствующим, а неверная подпись — предупреждение; в обоих случаях запускается
компилятор. Читатель без `publicKey` доверяет серверу и получает предупреждение, когда использует результат.

Сервер отвечает на два запроса, каждый с токеном, если он есть. `GET <url>/<slug>/<key>` отдаёт результат как ZIP-архив
или `404`, если его нет, а `<key>.sig` — его подпись. `PUT` по тем же путям сохраняет их и отвечает `200`, `201` или
`204`, а `HEAD` сообщает для `tazel cache push`, есть ли результат. Перенаправления не выполняются. Сервер, который
выдаёт ошибку или недоступен, — это предупреждение: сборка продолжается, и в рамках этой команды сервер больше не
опрашивается. [`tazel cache serve`](/docs/reference/commands#сервер-удалённого-кэша) — такой сервер.

## `outdirs`, `targets` и `pml`

```kotlin
outdirs {
  release = "build/release"
  debug = "build/debug"
}

targets {
  target("x86_64-pc-windows-msvc", "aarch64-apple-darwin")
}

pml {
  enabled = true
}
```

Выходные каталоги указываются относительно файла проекта и остаются внутри проекта. Артефакт называется по своей цели:
`build/debug/<name>.exe` для сборки, `build/debug/<name>.talameta` для проверки.

`targets` перечисляет целевые тройки LLVM, для которых предназначен пакет; по умолчанию — цель хоста. `check`, `build` и
`run` компилируют для хоста. `pml.enabled = false` предназначен для того, чтобы закрыть проекту Progmasoft Library
(`Progmasoft.*`); настройка записывается, но у компилятора пока нет для неё параметра.

## `sources`

```kotlin
sources {
  viget {
    push = true
    exclude("build/**/*")
  }

  executable {
    name = "Example"
    srcDir = "Sources"
    exclude("Sources/Generated")
    entry = "Example.Program"
  }

  library {
    name = "ExampleLibrary"
    viPkgType(ViPkgType.TALALIB, ViPkgType.STATICLIB)
    srcDir = "Sources"
    namespace = "Example.Library"
  }

  test("Unit") {
    testDir = "Tests/Unit"
  }
}
```

Цели в `sources` — это цели Tala; проекту, который собирают только его плагины, они не нужны. У проекта может быть любое
число исполняемых файлов и библиотек. `name` по умолчанию равен имени проекта, поэтому цель проекта без имени должна
назвать себя сама; имена чувствительны к регистру и уникальны в пределах своего вида. `srcDir` по умолчанию — `Sources`.

`entry` называет класс по его пространству имён: `Example.Program`. Этот класс предоставляет
`public static void Main()` без параметров, который запускает программу. Точка входа находится по пространству имён и
классу, а не по файлу: ни имена файлов, ни каталоги не обязаны повторять пространства имён. У библиотеки нет точки входа;
`namespace` называет её корневое пространство имён. `viPkgType` равен `TALALIB`, если библиотека не указывает иное;
другие виды — `STATICLIB` и `CDYLIB`.

Исходники цели — это каждый файл в её `srcDir`, имя которого оканчивается на `.tala`, написанное именно так. По
символическим ссылкам переход не выполняется. `exclude` принимает шаблоны относительно файла проекта, записанные через
`/`:

- `*` и `?` совпадают в пределах одного сегмента пути;
- сегмент `**` совпадает с любым числом сегментов;
- шаблон, который называет каталог, исключает всё внутри него.

Шаблоны сравниваются так, как хост сравнивает имена файлов: в Windows без учёта регистра, в остальных системах точно.

`test("Name")` объявляет именованный набор тестов; имя — один идентификатор, и объявить его можно один раз. `testDir` по
умолчанию — `Tests/<name>`. Тестовые исходники и тестовые артефакты никогда не попадают в `.vipkg`.
`sources.viget.exclude` убирает из упаковки дополнительные файлы.

## `dependencies`

```kotlin
dependencies {
  dependency("Publisher") {
    name = "Name"
    version = "1.2.3"
    stability = Stability.STABLE
  }

  dependency("Publisher") {
    name = "Toml"
    version = "1.0.0"
    feature = "TOML"
    defaultFeatures = false
    feature("Serde") { enabled = true }
  }

  localDependency { path = "Dependency.vipkg" }

  testDependency("Publisher") {
    name = "TestDep"
    version = "0.1.0"
  }

  localTestDependency { path = "TestDependency.vipkg" }
}
```

Зависимость — это пакет из ViGet, записанный как издатель, имя и точная версия. `stability` по умолчанию — `STABLE`.
Издатель — имя учётной записи Progmasoft с учётом регистра. ViGet — единственный удалённый источник: списка репозиториев
нет, и указать другой нельзя.

`feature = "TOML"` делает зависимость необязательной: она подключается, только когда включена фича `TOML` этого проекта.
`defaultFeatures` и `feature("Name") { enabled = true }` выбирают среди фич самой зависимости.

`localDependency` называет `.vipkg` в каталоге проекта. `testDependency` и `localTestDependency` служат только наборам
тестов. Пакет можно объявить один раз для каждого вида; два различающихся объявления одного пакета — ошибка.

Tazel записывает объявления и пока не загружает их, поэтому `check`, `build` и `run` отклоняют проект, который объявляет
зависимость сборки. Пространства имён стандартной библиотеки — не зависимости, и они никогда не объявляются.

## `execution`

```kotlin
execution {
  jobs = 8
  cpus = 6
  memory = "16g"
  memoryPerJob = "1g"
  keepGoing = true
  incremental = true
  profile = "build/trace.json"

  remote {
    url = "https://build.example.com"
    token = System.getenv("TAZEL_REMOTE_TOKEN")
  }
}
```

Весь блок необязателен, а [флаги](/docs/reference/commands#использование-машины) команды имеют приоритет над ним. В
workspace действует блок корня. `profile` указывается относительно файла проекта. `url` принимает `https` или `http`
только для этой машины.

## `workspace`

```kotlin
workspace {
  members("./Server", "../Shared", "Client")
  defaultMembers("./Server", "../Shared")
  exclude("OldProject")
}
```

Каждый участник — это каталог с собственным файлом проекта, записанный относительно этого файла проекта. Проекту, который
только собирает участников, нужен `project.name` и не нужны `sources`. `defaultMembers` — участники, с которыми работают
`tazel fmt` и `tazel lint` в корне; `exclude` убирает каталог из участников. См.
[workspace](/docs/reference/commands#workspace).

## `plugins`

Плагины расширяют DSL. Они объявляются в блоке `plugins`, который Tazel читает до компиляции остального файла:

```kotlin
plugins {
  plugin("Progmasoft") {
    name = "CMake"
    version = "0.1.0"
  }

  localPlugin {
    path = "plugin.jar"
  }
}
```

Плагин из ViGet ищется в кэше проекта, `.tazel/plugins`; плагин, которого нет в кэше, загружается из
`https://viget.progmasoft.com/dslplugins/tazel/<Publisher>/<Name>/`. Локальный плагин — это JAR в каталоге проекта. В
обоих случаях JAR описывает себя в `META-INF/tazel-plugin.properties` (издатель, имя, версия, версия API, импорты,
которые он добавляет в файл проекта) и предоставляет ровно один сервис `ProjectPlugin`. Tazel проверяет координату,
версию, версию API и дайджест SHA-256 до загрузки плагина; файл `<plugin>.jar.sha256` рядом с JAR фиксирует ожидаемый
дайджест. У плагина нет стабильности.

Плагин пишется на основе пакета `com.progmasoft.api.tazel.dsl.plugin`. Он может регистрировать расширения DSL,
добавлять метаданные и выполнять хук, когда проект готов. Плагин — доверенная логика сборки: он работает с полным
доступом JVM, и Tazel его не ограничивает. [Как написать плагин](/docs/extending/plugins) показывает, как плагин
собирается и загружается.

## Значения хоста и помощники

| Имя | Смысл |
| --- | --- |
| `OS` | операционная система, на которой работает Tazel: `OperatingSystem.LINUX`, `MACOS`, `WINDOWS`, `FREEBSD`, `OPENBSD`, `NETBSD` или `UNKNOWN` |
| `ARCH` | архитектура её процессора: `Architecture.X86_64`, `AARCH64`, `ARMV7H`, `RISCV64` или `UNKNOWN` |
| `panic(message)` | останавливает вычисление; команда завершается с этим сообщением |
| `eprint(value)` | пишет в стандартный поток ошибок |

```kotlin
if (OS == OperatingSystem.OPENBSD) panic("this project does not build on OpenBSD")
```

После своих блоков `project` и `compiler` файл проекта может прочитать то, что записал: `project.name`,
`compiler.standard`.

## Lock-файл

`LOCK.sqlite3` рядом с файлом проекта — база данных SQLite, которая записывает зависимости, объявленные проектом, и
плагины, которые его вычисляли. `tazel lock resolve` обновляет его; `check`, `build` и `run` обновляют его, когда он
больше не соответствует файлу проекта. Он записывает объявления, а не разрешённый граф зависимостей.

`tazel lock create-dump` записывает `LOCK.dump`: то же содержимое в виде SQL-текста, детерминированное и воспроизводимое
SQLite, для ревью и diff. `--path` записывает его в другой файл в уже существующей папке; см.
[команды](/docs/reference/commands). [Lock-файл](/docs/reference/lockfile) описывает его таблицы и то, когда его
записывает каждая команда.

## Настройка инструментов

`talafmt.kts`, `talalint.kts` и `tala-analyzer.kts` настраивают форматировщик, линтер и анализатор исходников Tala.
Каждый инструмент использует свои значения по умолчанию, если его файла нет.
