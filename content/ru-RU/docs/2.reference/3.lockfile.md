`LOCK.sqlite3` лежит рядом с файлом проекта. Это база данных SQLite, которая записывает то, что объявляет проект: его
зависимости с их фичами и плагины, которые вычисляли файл проекта, с дайджестом каждого JAR. Она записывает объявления, а
не разрешённый граф зависимостей; Tazel пока не умеет загружать пакеты из ViGet, поэтому разрешать нечего.

Коммитьте `LOCK.sqlite3` вместе с файлом проекта. Его текстовая форма, `LOCK.dump`, нужна для чтения и ревью изменений.

## Когда он записывается

| Команда | Что происходит с `LOCK.sqlite3` |
| --- | --- |
| `tazel lock resolve` | записывается для проекта и для каждого участника его workspace |
| `tazel check`, `build`, `run` | записывается перед компиляцией проекта, если он больше не отражает то, что объявляет проект |
| `tazel lock graph` | записывается, если отсутствует или устарел; с `--locked` устаревший файл вместо этого считается ошибкой |
| `tazel lock create-dump` | только читается |

«Устарел» определяется по содержимому: Tazel читает файл и сравнивает записанное в нём с тем, что объявляет файл проекта
сейчас. Файл старого формата, повреждённый файл и отсутствующий файл — все считаются устаревшими.

Новый lock-файл записывается во временный файл в том же каталоге, а затем перемещается поверх старого — атомарно, если
файловая система это позволяет, поэтому прерванная запись никогда не оставляет половину lock-файла.

## Формат 5

Таблица `metadata` хранит формат: `format_version` равен `5`. Формат 5 — это формат 4 со стабильностью `RC`, поэтому файл
формата 4 читается как есть и остаётся, пока проект не изменится. Lock-файл любого другого формата не читается; Tazel
просит выполнить `tazel lock resolve`, которая запишет текущий. Версии Tazel до формата 5 так же отклоняют файл формата 5.

| Таблица | Ключ | Столбцы |
| --- | --- | --- |
| `metadata` | `key` | `value`; хранит `format_version` |
| `packages` | `name`, `scope` | `stability`, `version`, `feature` (фича этого проекта, которая подключает пакет, или `NULL`), `default_features` (`0` или `1`) |
| `package_features` | `package_name`, `scope`, `feature` | `enabled` (`0` или `1`): фичи самой зависимости, которые проект включает или выключает |
| `local_packages` | `path`, `scope` | файлы `.vipkg`, которые называет проект, относительно файла проекта |
| `plugins` | `publisher`, `name` | `version`, `api_version`, `sha256` (64 шестнадцатеричные цифры) |

`name` в `packages` — это координата пакета, `Publisher.Name`. `scope` равен `BUILD` для `dependency` и
`localDependency`, `TEST` для `testDependency` и `localTestDependency`. Каждая таблица — `WITHOUT ROWID`: строка
определяется только своим ключом, поэтому один пакет нельзя записать дважды в одной области.

Для такого файла проекта:

```kotlin
dependencies {
  dependency("Publisher") {
    name = "Toml"
    version = "1.0.0"
    feature = "TOML"
    defaultFeatures = false
    feature("Serde") { enabled = true }
  }
  localDependency { path = "Libraries/Shared.vipkg" }
}
```

lock-файл содержит:

| Таблица | Строка |
| --- | --- |
| `packages` | `Publisher.Toml`, `BUILD`, `STABLE`, `1.0.0`, `TOML`, `0` |
| `package_features` | `Publisher.Toml`, `BUILD`, `Serde`, `1` |
| `local_packages` | `Libraries/Shared.vipkg`, `BUILD` |

## Текстовый дамп

```text
tazel lock create-dump
tazel lock create-dump --path reviews/Locks.sql
```

`LOCK.dump` — это SQL, который SQLite может воспроизвести: комментарий-заголовок, `PRAGMA foreign_keys=OFF;`, затем одна
транзакция с оператором `CREATE TABLE` каждой таблицы и её строками. Таблицы идут в порядке имён, а строки — в порядке
столбцов, поэтому один и тот же lock-файл всегда даёт одни и те же байты, и diff показывает только изменения.

Чтобы снова превратить дамп в базу данных:

```text
sqlite3 LOCK.sqlite3 < LOCK.dump
```

Дамп никогда не записывается поверх двоичного lock-файла, а его папка должна существовать; см.
[команду](/docs/reference/commands#writing-the-lockfile-as-text).

## Граф зависимостей

`tazel lock graph` рисует то, что записано в lock-файлах, поэтому сначала обновляет их. Каждый проект workspace
показан как корень, под ним — его пакеты из ViGet и локальные пакеты, а тестовые зависимости — под `[test]`. Пакет,
который подключает фича, показывается, только пока эта фича включена. Параметры описаны у
[команды](/docs/reference/commands#the-dependency-graph).
