Плагин — это JAR, который расширяет DSL проекта. Он может добавлять блоки, которые использует файл проекта, например
`cmake { }`, добавлять шаги в сборку проекта, записывать значения в его план и проверять проект, когда тот готов. Эта
страница показывает, как собирается плагин, как Tazel находит и проверяет его и что ему разрешено делать во время работы.

Плагин — это доверенная логика сборки. Он работает внутри Tazel с полным доступом JVM; Tazel проверяет, что JAR — тот
самый, который запросил проект, и не ограничивает того, что он делает.

## Использование плагина

Проект объявляет свои плагины в блоке `plugins`:

```kotlin
plugins {
  plugin("Publisher") {
    name = "CMake"
    version = "0.1.0"
  }

  localPlugin {
    path = "Tools/plugin.jar"
  }
}
```

- `plugin("Publisher") { name = ...; version = ... }` запрашивает плагин из ViGet. Сначала Tazel ищет в кэше плагинов
  проекта, `.tazel/plugins`; если подходящей версии там нет, он загружает плагин из
  `https://viget.progmasoft.com/dslplugins/tazel/<Publisher>/<Name>/` в кэш. Без `version` берётся новейшая версия,
  которая не отозвана и собрана для API плагинов этого Tazel; указанная версия берётся, даже если она отозвана.
- `localPlugin { path = ... }` называет JAR в каталоге проекта. Его издатель, имя и версия берутся из самого JAR.

Tazel читает этот блок **до** выполнения остального файла, небольшим парсером, который не выполняет никакого кода. Этот
парсер принимает только то, что показано в примере: `plugin("...")` и `localPlugin` с полями в виде простых строковых
литералов; значение, вычисленное из переменной или строкового шаблона, отклоняется. Комментарии и строки в других местах
файла пропускаются, поэтому слово `plugins` внутри них не принимается за блок.

Когда скрипт выполняется, блок снова объявляет те же плагины, и каждый плагин, найденный парсером, должен быть объявлен.
Пишите блок на верхнем уровне файла: внутри `if`, который не выполняется, его плагины остаются необъявленными, и команда
завершается ошибкой `resolved plugins were not declared by the script`.

## Сборка плагина

Плагин собирается с Gradle 9 и Gradle-плагином `com.progmasoft.tazel.plugin`, версия которого — это версия Tazel, для
которой собирается плагин. Progmasoft публикует Gradle-плагин по адресу `https://maven.progmasoft.com/tazel` рядом с API,
поэтому настройки сборки указывают этот репозиторий для плагинов. Репозиторий эксклюзивен для групп `com.progmasoft.tazel`
и `com.progmasoft.tazel.*`: Gradle ищет их там и больше нигде, а любой другой плагин, например плагин Kotlin, ищет в
Gradle Plugin Portal:

```kotlin
// settings.gradle.kts of the plugin
pluginManagement {
  repositories {
    exclusiveContent {
      forRepository { maven("https://maven.progmasoft.com/tazel") }
      filter { includeGroupByRegex("com\\.progmasoft\\.tazel(\\..*)?") }
    }
    gradlePluginPortal()
  }
}

rootProject.name = "cmake-plugin"
```

```kotlin
// build.gradle.kts of the plugin
plugins {
  kotlin("jvm") version "2.4.0"
  id("com.progmasoft.tazel.plugin") version "0.4.0.3"
}

repositories {
  mavenCentral()
}

version = "0.1.0"

kotlin { jvmToolchain(25) }

tazelPlugin {
  publisher = "Publisher"
  name = "CMake"
  pluginClass = "com.example.cmake.CMakePlugin"
  imports = listOf("com.example.cmake.dsl.*")
  description = "Configures and builds CMake projects."
  authors = listOf("Ada Lovelace <ada@example.com>")
  license = "MIT"
  homepage = "https://example.com/cmake"
  repository = "https://github.com/example/cmake-plugin"
}

dependencies {
  tazelApi()
}
```

Gradle-плагин

- добавляет репозиторий API, `https://maven.progmasoft.com/tazel`, только для группы `com.progmasoft.tazel`; Kotlin и всё
  остальное берутся из репозиториев сборки, здесь Maven Central;
- делает так, что `tazelApi()` означает `compileOnly` и `testImplementation` для `com.progmasoft.tazel:tazel-api` его
  собственной версии. API не упаковывается в JAR: Tazel предоставляет его и стандартную библиотеку Kotlin, когда
  загружает плагин;
- записывает в JAR дескриптор и запись сервиса ниже из `tazelPlugin { }`. Версия плагина — это версия проекта, если
  `tazelPlugin.version` не задаёт другую.

Затем `gradlew jar` записывает JAR плагина.

## JAR

JAR плагина содержит:

```text
com/example/cmake/CMakePlugin.class
com/example/cmake/dsl/CMake.class                                  the functions it adds to the DSL
META-INF/tazel-plugin.properties                                   the descriptor
META-INF/services/com.progmasoft.api.tazel.dsl.plugin.ProjectPlugin
```

### Дескриптор

```properties
publisher=Publisher
name=CMake
version=0.1.0
apiVersion=2
imports=com.example.cmake.dsl.*
description=Configures and builds CMake projects.
author.0=Ada Lovelace <ada@example.com>
license=MIT
homepage=https\://example.com/cmake
repository=https\://github.com/example/cmake-plugin
```

| Ключ | Правило |
| --- | --- |
| `publisher` | один идентификатор: имя учётной записи Progmasoft |
| `name` | один идентификатор |
| `version` | точная версия: `A.B.C`, затем при необходимости `.D`, `.E` и `-METADATA` |
| `apiVersion` | API плагинов, для которого он собран; Tazel загружает только `2`, текущую `PROJECT_PLUGIN_API_VERSION` |
| `imports` | необязательно; пакеты или классы через запятую, которые файл проекта импортирует по умолчанию, например `com.example.cmake.dsl.*` |
| `description`, `author.0`, `author.1`, ..., `license`, `homepage`, `repository` | для Tazel необязательны; ViGet показывает их на странице плагина. `license` — выражение SPDX. |

Импорт должен быть именем с точками, которое может оканчиваться на `.*`; всё остальное отклоняется.

### Сервис

`META-INF/services/com.progmasoft.api.tazel.dsl.plugin.ProjectPlugin` называет класс, который реализует
`ProjectPlugin`:

```text
com.example.cmake.CMakePlugin
```

Запись называет ровно один класс; строка может заканчиваться комментарием `#`. Класс реализует `ProjectPlugin` и имеет
открытый конструктор без параметров. Кто такой плагин, определяет только дескриптор: класс не указывает ни издателя, ни
имени, ни версии.

## API

API — это `com.progmasoft.tazel:tazel-api`, пакеты `com.progmasoft.api.tazel` и вложенные. Плагин реализует
`ProjectPlugin`:

```kotlin
fun interface ProjectPlugin {
  fun apply(context: ProjectPluginContext)
}

interface ProjectPluginContext {
  val projectRoot: Path
  val host: Host

  fun registerExtension(name: String)
  fun contribute(key: String, value: String)
  fun onFinalize(action: (ProjectSummary) -> Unit)
}
```

| Вызов | Что он делает |
| --- | --- |
| `projectRoot` | каталог файла проекта |
| `host` | операционная система и архитектура, на которых работает Tazel |
| `registerExtension(name)` | закрепляет имя DSL, например `cmake`, за этим плагином. Имя — это один идентификатор, и два плагина не могут закрепить одно и то же. |
| `contribute(key, value)` | записывает значение в план проекта. Ключ начинается с буквы или `_` и содержит не более 128 букв, цифр, `_`, `.` или `-`; каждый ключ записывается один раз на плагин, и значение не может быть пустым. |
| `onFinalize(action)` | выполняет `action` с `ProjectSummary` (имя, версия, режим сборки, выходной каталог) после окончания скрипта — для проверок, которым нужен весь проект |

Расширения и вклады каждого плагина попадают в план проекта и в его lock-файл.

### Блоки и шаги сборки

Блок, который пишет файл проекта, например `cmake { }`, — это функция, которую плагин определяет в одном из своих
`imports`. Она запрашивает у `PluginExtensions` область своего расширения, что завершается ошибкой, если проект не
объявил плагин, который её зарегистрировал, и добавляет работу блока как шаги сборки:

```kotlin
package com.example.cmake.dsl

import com.progmasoft.api.tazel.dsl.TazelPluginDsl
import com.progmasoft.api.tazel.dsl.plugin.PluginExtensions

@TazelPluginDsl
class CMakeScope {
  var enabled = false
  internal val definitions = linkedMapOf<String, String>()

  fun define(vararg values: Pair<String, String>) = definitions.putAll(values)
}

fun cmake(block: CMakeScope.() -> Unit) {
  val settings = CMakeScope().apply(block)
  if (!settings.enabled) return
  val scope = PluginExtensions.require("cmake")
  scope.buildStep("configure") { context ->
    val cmake = context.findProgram("cmake") ?: context.fail("cmake was not found on PATH")
    val exitCode =
      context.run(
        listOf(cmake.toString(), "-S", ".", "-B", context.workDirectory.toString()) +
          settings.definitions.map { (key, value) -> "-D$key=$value" }
      )
    if (exitCode != 0) context.fail("cmake exited with $exitCode")
  }
}
```

`tazel build` и `tazel run` выполняют шаги проекта в том порядке, в каком они были добавлены, до компиляции его целей
Tala. Для `tazel build` проекту, плагины которого добавляют шаги, цель Tala не нужна; `tazel run` нужен исполняемый файл
для запуска, и он выполняет шаги его проекта перед компиляцией. Шаг выполняется с `BuildContext`:

| Член | Что это |
| --- | --- |
| `projectRoot`, `host`, `buildMode` | проект, машина и `DEBUG` или `RELEASE` |
| `project` | `ProjectSummary` проекта: его имя, версия, режим сборки и выходной каталог |
| `outputDirectory` | абсолютный каталог, в который режим сборки проекта пишет артефакты |
| `workDirectory` | каталог шага для промежуточных файлов: `.tazel/build/<Publisher>.<Name>/<step>` проекта, одинаковый в каждой сборке |
| `status(verb, message)`, `warn(message)` | печатает строку в выводе Tazel |
| `run(command, directory, environment)` | запускает программу с переменными в дополнение к переменным Tazel и возвращает её код выхода; то, что она печатает, идёт в вывод Tazel |
| `capture(command, directory, environment)` | запускает программу как `run`, но возвращает её код выхода и вывод, вместо того чтобы показывать их: для пробы, неудача которой — это ответ, или программы, вывод которой читает шаг |
| `findProgram(name)` | программа в `PATH` с расширением исполняемых файлов хоста, или `null` |
| `fail(message)` | останавливает сборку с координатой плагина, именем шага и сообщением |

`@TazelPluginDsl` помечает области плагина, чтобы вложенный блок не мог по ошибке обратиться к членам окружающего блока.

Сбой внутри `apply`, финализатора или шага останавливает команду с координатой плагина и сообщением исключения, например
`plugin 'Publisher.CMake' failed while finalizing the project: the CMake plugin needs a CMakeLists.txt`.

## Как Tazel загружает плагин

1. **Разрешение.** Локальный плагин должен быть обычным файлом, а не символической ссылкой, внутри каталога проекта, в
   том числе после разрешения его настоящего пути. Плагин из ViGet ищется в `.tazel/plugins` по издателю, имени и, если
   указана, версии; если его там нет, его индекс `index.json` и его JAR `<Version>/<Name>-<Version>.jar` загружаются из
   ViGet, и JAR сохраняется, только если его SHA-256 совпадает с указанным в индексе.
2. **Проверка.** Tazel читает дескриптор, проверяет каждый ключ и вычисляет дайджест SHA-256 JAR. Если рядом с JAR лежит
   файл `<plugin>.jar.sha256`, его первое слово должно быть этим дайджестом в шестнадцатеричной записи строчными буквами.
3. **Активация.** JAR помещаются в собственный загрузчик классов; для каждого плагина класс, который называет его запись
   сервиса, создаётся открытым конструктором, и `apply` выполняется в порядке объявлений.
4. **Настройка.** Выполняется файл проекта. Его блок `plugins` снова объявляет те же плагины; каждый должен быть разрешён
   на шаге 1 с той версией, которую называет блок. Блоки плагинов добавляют свои шаги сборки.
5. **Завершение.** После скрипта каждый финализатор выполняется со сводкой проекта, и записи плагинов добавляются в его
   план.
6. **Фиксация.** Издатель, имя, версия, версия API и дайджест каждого плагина записываются в `LOCK.sqlite3`; см.
   [Lock-файл](/docs/reference/lockfile).
7. **Сборка.** `tazel build`, а также `tazel run` для проекта запускаемого исполняемого файла выполняют шаги сборки.
   JAR остаются открытыми до конца команды.

## Как попробовать плагин

Самый быстрый цикл — отдельный проект, который указывает JAR как локальный плагин:

```kotlin
plugins {
  localPlugin { path = "build/libs/cmake-plugin-0.1.0.jar" }
}

project { name = "Demo" }

cmake {
  enabled = true
  define("BUILD_TESTS" to "OFF")
}
```

`tazel build` выполняет шаги плагина. `tazel lock resolve` загружает плагин, выполняет скрипт и записывает lock-файл,
ничего не собирая; затем `tazel lock create-dump` показывает плагин так, как его записал lock-файл.
